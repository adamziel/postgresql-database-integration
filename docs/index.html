How to read this: Rows labeled mysql and sqlite are native WordPress database baselines and do not use DuckDB. Rows labeled mysql_attach and sqlite_attach are DuckDB rows: WordPress talks to DuckDB, and DuckDB talks to the attached database. DuckDB external file/object-store rows hydrate tables into DuckDB and flush them back to the target storage.
Concurrency interpretation: MySQL is the server-backed baseline. SQLite and DuckDB are file-backed paths where writes are constrained by backend locking. DuckDB external storage adds a hydrate/flush cycle, so higher HTTP concurrency primarily creates queueing instead of linear throughput scaling. Compare the low-concurrency and high-concurrency p95 values in the summary table to see queueing pressure.
